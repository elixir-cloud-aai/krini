{{- $ingress := .Values.krini.ingress.enabled -}}
{{- $httpRoute := .Values.krini.httpRoute.enabled -}}
{{- $exposed := or $ingress $httpRoute (include "krini.routeEnabled" .) -}}
Krini is being deployed as release {{ .Release.Name }} in namespace {{ .Release.Namespace }},
with the image {{ include "krini.image" . }}.
{{- if and $ingress (not .Values.krini.ingress.https.enabled) (.Capabilities.APIVersions.Has "route.openshift.io/v1") }}

WARNING: This cluster serves OpenShift Routes, but the chart created an
Ingress without TLS, which OpenShift serves without TLS. Set
krini.ingress.enabled to false to get a Route with TLS instead, or enable
krini.ingress.https for a certificate of your own (see "Exposing Krini" in
the operator guide).
{{- else if and $ingress (not .Values.krini.ingress.https.enabled) }}

NOTE: The Ingress has no TLS (krini.ingress.https.enabled is false), so TLS
must be terminated in front of the cluster: Krini sets secure cookies and
sends users back to {{ $origin }} after the login.
{{- end }}
{{- if $httpRoute }}

The HTTPRoute serves Krini via the Gateway in krini.httpRoute.parentRefs:
make sure that its listener terminates TLS for {{ .Values.hostName }}, and
check that the route is accepted with
`kubectl get httproute {{ $fullname }} -n {{ .Release.Namespace }} -o yaml`.
{{- end }}
{{- $originHost := (urlParse $origin).host | default "" | lower | trimSuffix ":443" -}}
{{- if and .Values.hostName (ne (.Values.config.redirectToAppOrigin | toString) "false") (ne (.Values.hostName | lower) $originHost) }}

WARNING: hostName ({{ .Values.hostName }}) isn't the host of
config.appOrigin ({{ $origin }}): Krini redirects every request at
{{ .Values.hostName }} to {{ $origin }}. Make sure that {{ $origin }} reaches
Krini with its own host name (a proxy must pass on the Host header), or
browsers loop; or set config.redirectToAppOrigin to false (see "Several
addresses" in the operator guide).
{{- end }}
{{- if not $exposed }}

WARNING: Neither an Ingress, an HTTPRoute nor an OpenShift Route was
created, so Krini is only reachable within the cluster, unless resources
outside the release expose it at {{ $origin }}.
{{- end }}

Check the rollout and test the release with:

  kubectl rollout status deployment/{{ $fullname }} -n {{ .Release.Namespace }}
  helm test {{ .Release.Name }} -n {{ .Release.Namespace }}

Then open {{ $origin }} in a browser. Register
{{ .Values.config.oidcRedirectUri | default (printf "%s/auth/api/callback" (trimSuffix "/" $origin)) }}
as a redirect URI of each login provider's client, and see "Service
configuration" in the operator guide for what the TES and WES services need.
