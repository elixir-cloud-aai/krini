The HTTPRoute serves Krini via the Gateway in krini.httpRoute.parentRefs:
make sure that its listener terminates TLS for {{ .Values.hostName }}, and

`kubectl get httproute {{ $fullname }} -n {{ .Release.Namespace }} -o yaml`.
{{- end }}
{{- if not $exposed }}

WARNING: Neither an Ingress, an HTTPRoute nor an OpenShift Route was
created, so Krini is only reachable within the cluster, unless resources
outside the release expose it at {{ $origin }}.
{{- end }}

Check the rollout and test the release with:

  kubectl rollout status deployment/{{ $fullname }} -n {{ .Release.Namespace }}
  helm test {{ .Release.Name }} -n {{ .Release.Namespace }}

Then open {{ $origin }} in a browser. Register
{{ .Values.config.oidcRedirectUri | default (printf "%s/auth/api/callback" (trimSuffix "/" $origin)) }}
as a redirect URI of each login provider's client, and see "Service
configuration" in the operator guide for what the TES and WES services need.
