The first release of Krini, rewritten as a Next.js web app: browse the GA4GH
services of a Cloud Registry, log in with any OpenID Connect provider (LS
Login for ELIXIR On-Cloud), and run tasks on GA4GH Task Execution Service
(TES) and workflows on GA4GH Workflow Execution Service (WES) instances with
your own access token. Krini is published as a signed container image,
`docker.io/elixircloud/krini:0.1.0`, that takes all its settings when it
starts, and a signed Helm chart attached to this release; the
[documentation](https://krini.readthedocs.io/en/latest/) covers its use,
deployment and configuration.

## Features

- Browse the services of a Cloud Registry, and run and follow WES workflows on them, in the rewritten Next.js app (#40, #42, #61)
- Run, follow and cancel TES tasks, with your access token sent with every TES and WES request, on Cloud Components 2.0.0-alpha.51 (#41, #44, #91, #90)
- Open the details of a WES run (state, logs, outputs) from the run list (#66, #100)
- Start from a minimal dashboard that leads to tasks and workflows (#67, #108)
- Log in with any OpenID Connect provider, with access tiers from group claims and a link to request compute access (#43, #45, #70)
- Copy your access token for the CLI and APIs (#46, #61)
- Keep the light or dark theme over reloads (#13, #61)
- Read a privacy notice, reachable before login and set up per deployment (#9, #64)
- Deploy Krini with a Helm chart, released and signed with each version (#52, #92, #94, #95)

## Security

- Send a Content Security Policy with a new nonce for each request, and the headers `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy` and, in production, `Strict-Transport-Security`; serve the code editor's workers from Krini instead of a CDN (#112, #120)
- Check the `Origin` of token refreshes against `APP_ORIGIN`, as for logouts; revoke the refresh token at the provider on logout where it offers token revocation (RFC 7009), and keep a refresh in flight from undoing a logout (#106, #111, #119)
- Keep local environment files and keys out of the image and the build context (#53, #68)

## Fixes

- End the session when the provider rejects the refresh token (RFC 6749) or sends an ID token of another user or issuer, not on every refresh error: keep it and retry with backoff while the provider is unavailable, refresh in one tab at a time, and no longer send visitors with a stale session cookie to the login page (#111, #119)
- Keep the user logged in when the provider sends no new ID token on refresh, and reject a refreshed ID token of another user or issuer (#111, #119)
- Ship the `NOTICE` file in the image, now with the notice of the Ace editor (#112, #120)
- Redirect logins to the app's public origin (`APP_ORIGIN`) instead of the server's listening address (#83, #84)
- Render the WES service information without a request from the server to its own `APP_ORIGIN` (#104, #110)
- Remove leftovers of the old UI from the navigation (#67, #108)
